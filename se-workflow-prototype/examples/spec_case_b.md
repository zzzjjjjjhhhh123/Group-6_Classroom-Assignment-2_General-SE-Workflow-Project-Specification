# 产品：到店生活 App（案例B）

## 项目目标

做本地生活到店场景的交易闭环：用户找店、买券、到店核销，商家看核销数据。第一期只覆盖单城市、单品类，不做配送。

## 功能模块

### 手机号登录与实名

- [P0] 支持手机号验证码登录，支持一键登录
- [P1] 购买前需完成实名认证，认证信息脱敏存储

### 门店与商品

- [P0] 支持按距离和品类筛选门店列表，展示评分与人均价
- [P1] 门店详情展示营业时间、地址、电话与在售团购
- [P0] 支持关键字搜索门店与商品

### 团购下单

- [P0] 支持选择商品规格、数量并提交订单，库存不足时明确提示
- [P0] 支持订单超时未支付自动取消（15 分钟）
- [P1] 支持优惠券抵扣，一单限用一张

### 支付与核销

- [P0] 支持微信支付，支付成功回调后生成核销码
- [P0] 商家端输入核销码完成核销，重复核销需拦截
- [P1] 支持退款申请，审核通过后原路退回

### 评价

- [P0] 支持对已完成订单发表图文评价，评价仅一次
- [P1] 支持商家回复评价

### 商家后台

- [P0] 商家可维护门店信息与商品上下架
- [P0] 商家可查看看板：订单量、核销量、退款率
- [P1] 支持导出订单明细

## 非功能要求

- [P0] 支付相关接口必须幂等，重复回调不产生重复订单
- [P0] 订单与支付数据需审计留痕，保留 180 天
- [P1] 大促期间下单接口 P99 响应不超过 800ms

## 约束

- 只做移动端，不做 PC 站点
- 后端 Java Spring Boot，数据库 MySQL
- 支付接入微信支付服务商模式

## 验收条件

- 用户能完成"找店—下单—支付—到店核销"完整链路
- 同一核销码第二次核销被明确拒绝
- 商家看板数据与订单明细一致
